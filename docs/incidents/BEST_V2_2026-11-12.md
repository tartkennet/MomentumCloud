## Repair

The existing workflow now has a separate close_watch job. A scheduled afternoon run remains alive until the XNYS close plus 15 minutes and dispatches the same audited account workflow if that session is not published. It does not require another cron event. The account and watcher have separate job-level concurrency locks, so the watcher cannot block its own child or intraday account updates. The watcher gets Actions write permission only to dispatch the existing workflow on main; it receives no market or broker credentials and never writes a journal.

The watcher can start within 4.5 hours of the close allowance, fitting within GitHub's job duration limit together with bounded child attempts. Both actual November 12 afternoon runs (16:54 and 20:47 UTC) were inside that window. It follows the NYSE holiday/half-day calendar and US DST, independent of Swedish DST. It waits for the child's successful production checks and verifies the exact session in the published journal. Three failed child attempts or a child timeout produce an explicit failed job. No cron schedules were added. A waiting runner can remain allocated for up to 4.5 hours on a trading day. If GitHub never starts any afternoon workflow or its runners are unavailable, this same-platform fallback cannot execute; the API independently marks the missing close as overdue.

The account now logs and publishes a close-verification receipt for every selected/held ticker, cross-checks the ledger's dated marks against the source bars, and rejects a stale valuation date. Known collection error codes are explicit and redacted. The API reports CLOSE_VALUATION_OVERDUE, the missing expected session and the actual last verified session. The UI labels stock daily changes with the actual price date, and shows NAV and portfolio day change to two SEK decimal places.
