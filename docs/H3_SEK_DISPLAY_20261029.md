# H3 SEK presentation, separate from validation

The 100,000 SEK display portfolio uses proportional virtual units of the actually recorded H3 USD account. Once the first accepted paper session and its dated FX fixing exist, freeze `scale = 100000 / (first_accepted_USD_NAV * initial_USDSEK)`. Scale quantities, cash, receivables and fees by that constant. Holdings can be fractional; this is explicitly a display replica, not another whole-share strategy or separately executed brokerage account. No H3 source, signal, parameter, gate, accepted fill or paper checkpoint is changed.

All simulated transactions come from the accepted checkpoint, with a deterministic ID, original signal/session dates, original USD price and scaled costs. A market trade's 09:30 America/New_York timestamp is the original model's regular-open convention, including DST, not a claim of a broker/tick timestamp. Corporate events use dates without invented execution times. Average purchase cost includes entry fees and follows splits/partial sales. Unresolved acquisition/distribution basis remains missing rather than guessed. The complete original trade list is retained, including cancelled orders and corporate events.

ECB reference fixings give SEK per USD as `(SEK per EUR)/(USD per EUR)`. Preserve observed fixings and the funding anchor in the separate valuation branch. Mark portfolio and SPY with the same FX basis, including USD cash. Use the last reference fixing available before a purchase session for indicative purchase cost in SEK; it is not an actual currency execution. No FX conversion charge or tax is claimed. More than seven calendar days without a recent fixing blocks a new SEK valuation. Missing historical rates block the graph and daily statistics rather than creating fake intervals.

Market access uses the existing GitHub market-data key, never a key in the browser. Query the provider's unified snapshot with explicit ticker filtering; only explicit timeframe metadata can verify realtime rights. Otherwise show timestamped available snapshots as sampled/delayed presentation, with provider latency unverified, or fall back to dated raw closes. Check unbooked splits/dividends before marking the previous account's quantities with a new session's quotes. A pending economic event forces comparable accepted closes, including SPY, until the actual paper account books the event. Current marks never enter the frozen validation NAV or generate a signal or fill.

The original paper supervisor exports a safe `h3-account.json` to its existing observation branch only after independent acceptance and durable preservation. A separate lightweight workflow updates `h3-sek-valuations` every 15 minutes, 13–22 UTC on weekdays, and after successful main-branch paper collection. Its concurrency and publication branch are separate so quote updates cannot cancel or overwrite paper work. Both data branches disable Vercel deployments. Git histories preserve prior exports; encrypted raw inputs and immutable original release archives remain unchanged.

The API reports synchronization, delay and delivery problems. No observations means a clearly labelled configured budget, null return and no fabricated holdings, transactions or curve. The new light-first app has five tabs; technical details and historical backtests are under More, and the previous dashboard is retained at `/legacy.html`. No automatic live approval or real orders exist.
